## v0.1.1 变更：构件 ID 命名规范（16:40 前后）

- **动机**：`YZ-01` 类缩写有撞名风险（YZ 可指檐柱/游柱/圆作……），ID 应完整体现构件拼音
- **决策（讨论后选定方案 B）**：构件 ID = `{类型全拼小写}_{序号}`，如 `yanzhu_01`
  - 与缝编码 `{KIND}_{SUFFIX}` 统一用下划线分隔
  - 前缀 = type 字段 = 数据文件名，零转换；构件小写 / 缝 KIND 大写，天然区分两个命名空间
  - 落选：`yanzhu-01`（连字符与轴线风格割裂）、`YANZHU_01`（全大写多音节拼音可读性差，且与 type 字段大小写不一致）
- **实施**：yanzhu.json 6 个实例 / tests 断言 / coding-system.md 示例更新；
  member.schema.json 新增 ID 正则 `^[a-z][a-z0-9]*_[0-9]+$`（自由字符串 → 强约束）
- **验证**：10 测试全过；jsonschema 校验新数据通过、旧格式（YZ-01/yanzhu-01 等）全部正确拒绝；重建产物 model_spec.json 含 yanzhu_01..06
- **环境**：venv 中 reportlab/jsonschema 需重装（原因待查，疑 venv 重建）；make 需指定 `PY=venv路径`
