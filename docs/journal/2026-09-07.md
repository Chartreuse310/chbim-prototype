# 开发日志 · 2026-09-07

> 格式：目标 / 尝试 / 成败 / 结论 / 下一步

## 目标

建立 CHBIM Prototype V1 仓库并打通「D 输入 → 缝编码解析 → yanzhu
几何 → 三视图 + 图纸导出 → Web 工作台」端到端可行性链路。

## 关键决策（与用户对齐）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 交互层 V1 形态 | **Web 工作台** | 用户选择（HTML/JS + Python + three.js 预览） |
| `yanzhu[CAO_Fo,CAO_Ro]` 定位语义 | **交点定位** | 一横一纵的缝交点即为构件中心；两条平行缝的写法待 V1.1 pattern 语法解决 |
| 开源协议 | **MIT** | 最宽松，研究者引用无负担；进程级调用 OpenSCAD 不受其 GPL 传染 |
| V1 构件范围 | **仅 yanzhu** | 按用户最小可行目标；槫缝/间缝在图纸中以辅助线形式呈现 |

## 技术验证（决定 sheet 管线设计）

| 验证项 | 结果 | 结论 |
|---|---|---|
| OpenSCAD 2026.06 的 OBJ 导出 | ✅ 原生支持 | 不用 trimesh 兜底（但保留方案） |
| OpenSCAD 2D SVG 输出格式 | ✅ 纯 `M/L/Z` 多边形（mm 单位） | 解析器只需简单 regex，圆自动离散为多边形 |
| 导出器 Y 轴处理 | ✅ `emitted_y = -geometry_y` | 解析时翻回几何坐标 |
| PDF 渲染方案：cairosvg | ❌ 系统 cairo 库依赖 | 改用 reportlab |
| PDF 渲染方案：reportlab | ✅ 自带 CID 字体 `STSong-Light`，纯 Python | 内置中文支持，零系统依赖 |
| sips PDF→PNG 渲染 | ⚠️ 失真 | 已知问题，pypdf 已验证 PDF 内容完整；用户用真实 PDF 查看器即可 |

## 实施

- 构建层：4 个 .scad 文件（units / axes / column / assembly），共约 50 行
- 数据层：2 个 JSON 数据 + 2 个 JSON Schema
- 粘合层：4 个 Python 模块（resolver / codegen / openscad / pipeline），约 350 行
- 图纸管线：views.py（解析） + compose.py（排版 + 双渲染），约 350 行
- Web 工作台：server.py（标准库 HTTP） + index.html（前端单页），约 300 行
- 测试：resolver 单元测试 + 端到端冒烟测试
- 文档：6 个 ADR + DECISIONS 索引 + coding-system + PROGRESS + README + LICENSE
